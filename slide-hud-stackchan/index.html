MAVLink: 姿勢を送る

  • BMI270 を 100Hz で読む
  • 相補フィルタで roll / pitch を推定
  • ATTITUDE を 20Hz で送信
  • 起動後 2 秒は水平に静止 → 0 度として扱う

注意 既知の課題

ロールHUD で左右が逆だったため、符号を反転

ヨー磁気補正なしで、時間とともにずれる

4 / 15 · 姿勢を送る · 目安 0:50 · 累計 2:30 / 9:10

内蔵の IMU を 100Hz で読み、相補フィルタで傾きを推定しています。
それを ATTITUDE として 20Hz で地上局に送っています。
起動直後の 2 秒間は、機体を水平に置いて静止させます。その姿勢を 0 度として扱います。
ロールは、HUD で見ると左右が逆だったので、符号を反転しています。
ヨーは磁気補正が無いので、時間とともにずれます。これは正直に残っている課題です。

役割: IMU → ATTITUDE。出典 direction-win.md 3 章。水平の取り直しは QGC の Vehicle Setup > Sensors の「Level horizon」（約 2 秒、ARM 中は不可）。

MAVLink: ARM とモードの安全設計

  • 起動直後は HOLD · DISARMED
  • ARM は、地上局とのリンクが生きている間だけ受け付ける
  • リンクが切れたら、自動で DISARM
  • 再接続しても、自動では ARM しない

機体を勝手に動かさないための設計

5 / 15 · ARM とモードの安全設計 · 目安 0:50 · 累計 3:20 / 9:10

状態は、モードと ARM 状態の 2 つです。起動直後は HOLD で DISARMED です。
ARM は、地上局とのリンクが生きているときだけ受け付けます。
リンクが切れたら、自動で DISARM します。再接続しても、自動では ARM しません。
機体を勝手に動かさないための設計です。

役割: 安全側の設計。出典 direction-win.md 4 章。

MAVLink: 頭部を動かす

  • バーチャルスティック → 頭部サーボの角度
  • 動くのは ARM 中かつ MANUAL のとき
  • 入力が 500ms 届かなければ中立に戻す
  • 可動範囲は設定ファイルの上下限を超えない

対応 符号は反転

xチルト

yパン

注意Y 軸は中立 90° から 0〜90° のみ

6 / 15 · 頭部を動かす · 目安 0:40 · 累計 4:00 / 9:10

地上局のバーチャルスティックの入力を、頭部サーボの角度に変えています。
動くのは、ARM 中で、かつ MANUAL のときだけです。
入力が 500 ミリ秒届かなければ、中立に戻します。
可動範囲は、設定ファイルの上下限を超えません。
注意点が 1 つあります。Y 軸は、中立の 90 度から 0 度から 90 度までしか動きません。両側に振るには、設定を変える必要があります。

役割: 操作と安全側の制限。出典 direction-win.md 5 章。[要確認]: 「500ms」はデフォルト値（README 記載）。機体での値は未確認。

Stack-chan
→ MAVLink
telemetry.py
→ POST

→ GET 100ms
hud.js
  • 傾き・方位 ← ATTITUDE
  • モード・アーム ← HEARTBEAT
  • 位置 ← GLOBAL_POSITION_INT
  • 速度・高度 ← VFR_HUD
  • 3 秒以上値が来ない → NO LINK
  • 位置は、送られるまで POST されない

7 / 15 · MAVLink → HUD · 目安 0:50 · 累計 4:50 / 9:10

Stack-chan が送る MAVLink は、もともと地上局用です。
PC の telemetry.py が同じ MAVLink を受けて、最新の値を serve.py に送ります。
デッキの HUD は、そこから 100 ミリ秒ごとに値を読んで、表示を更新します。
3 秒以上値が来なければ、HUD は NO LINK になります。

役割: 経路と対応表。出典 direction-wsl.md 2.3・2.4、telemetry.py、en-2/hud.js。[要確認]: 送信先（UDP の IP とポート）、heartbeat の type と mode 名、送信元の system ID（direction-wsl.md 2.3）。ネットワーク（WSL2 の NAT）は付録に回す。

撫でで操作する

  • 頭を 前から後ろへ 撫でる → 次のスライド
  • 頭を 後ろから前へ 撫でる → 前のスライド
  • 頭上 2 回タップ → 挨拶
  • 頭上 3 回タップ → うなずき
  • 頭上 4 回タップ → 一回転

10 / 15 · 撫でで操作する · 目安 0:50 · 累計 7:00 / 9:10

頭を撫でると、スライドが進みます。
2 回タップすると挨拶、3 回でうなずき、4 回で一回転します。
発表者は、手元で何も押さなくて済みます。

役割: 操作一覧。出典 direction-win.md 6 章。WSL 側が受けるのは control の next / prev だけ（stackchan-bridge.js）。挨拶などの動作は機体側。

スライドごとの指定

<section data-stackchan-motion="nod" data-stackchan-led='{"pattern":"breath","color":"#0078C8","speed":5}'>
  • data-stackchan-expression: neutral / happy / sad / angry / doubt / sleepy（省略時は 6 枚ごとの循環）
  • data-stackchan-motion: nod / shake / spin / none
  • data-stackchan-led: 次のスライドまで保持
  • 吹き出し: 見出し（または data-stackchan-title）、40 文字まで

役割: 書き方。出典 stackchan-bridge.js。[要確認]: 表情（data-stackchan-expression）は、WSL の bridge が送っていないので、このデッキでは扱わない（direction-wsl.md 2.2）。

注意点

  • 手動で操作している間は、スライドによる首の動きは止まる
  • https のページからは ws:// に接続できない → PC でローカル配信
  • HUD は serve.py 経由で開く（file:// では動かない）
