## 3. HUD（QGC の姿勢表示）

**スライド**: 機体の傾きが HUD に出るデモ（動画または写真）
**画面注記**: 「ヨーは磁気補正なしのためドリフトする」

**台本**
> 内蔵の IMU（BMI270）を 100Hz で読み、相補フィルタでロールとピッチを推定しています。
> それを ATTITUDE として 20Hz で QGC に送っています。
> 起動直後の 2 秒間は、機体を水平に置いて静止させます。その姿勢を 0 度として扱います。
> ロールは、HUD で見て左右が逆に出たので、出力の符号を反転しています。
> ヨーは磁気補正が無いので、時間とともにずれます。ここは正直に残っている課題です。

**補足（発表者用）**
- 水平の取り直しは、QGC の Vehicle Setup > Sensors の「Level horizon」から行えます（約 2 秒、ARM 中は不可）。

## 4. ARM とモード（安全側の設計）

**スライド**: 状態遷移の図（HOLD / MANUAL × DISARMED / ARMED）

**台本**
> 状態は「モード」と「ARM 状態」の 2 つです。起動直後は HOLD と DISARMED です。
> ARM は、GCS のリンクが生きているときだけ受け付けます。
> GCS の接続が切れたら、自動で DISARM します。再接続しても、自動では ARM しません。
> ここは、機体を勝手に動かさないための設計です。

## 5. 頭部を動かす（MANUAL で ARM 中のみ）

**スライド**: スティック → 頭部の対応図（x → チルト、y → パン。符号は反転）

**台本**
> QGC のバーチャルスティックの入力を、頭部サーボの角度に変えています。
> 動くのは、ARM 中で、かつ MANUAL のときだけです。
> 入力が 500ms 届かなければ、中立に戻します。
> 可動範囲は設定ファイルの上下限を超えません。
> ひとつ注意があります。内蔵サーボの Y 軸は、中立 90 度に対して 0 から 90 度の範囲しか動きません。両側に振るには、設定を変える必要があります。

## 6. スライドモード（reveal.js と連携）

**スライド**: 構成図（ブラウザ（reveal.js）↔ Stack-chan の `ws://<ip>/servo-ws`。スライド操作は PC サーバーを挟まない。ただし HUD（(C)）を使う場合は、PC で `serve.py` が必要）

**台本**
> 発表資料は reveal.js で作っています。ブラウザが、Stack-chan に直接 WebSocket で接続します。間に PC のサーバーは挟みません。
> 有効にするには、設定画面で「スライドモード」を ON にします。

**スライド**: 操作の一覧
- 頭の前から後ろへ撫でる → 次のスライド
- 後ろから前へ撫でる → 前のスライド
- 頭上 2 回タップ → 挨拶（intro / outro を交互）
- 頭上 3 回タップ → うなずき
- 頭上 4 回タップ → 一回転

**台本**
> 頭を撫でると、スライドが進みます。
> 2 回タップで挨拶の音声、3 回でうなずき、4 回で一回転です。
> スライドが切り替わるたびに、表情が変わります。6 枚ごとに「普通、うれしい、疑い、悲しい、怒り、眠い」の順で循環します。
> **[要確認]**: WSL 側の `stackchan-bridge.js` は、表情を送っていません（送るのは slide / motion / led / title）。循環を機体側でやっているか、WSL から `expression` を送るのかを決めてください（`direction-wsl.md` 2.2）。

**スライド**: スライドごとの指定（HTML の `data-` 属性）
- `data-stackchan-motion`: nod / shake / spin / none
- `data-stackchan-expression`: 表情を明示
- `data-stackchan-led`: LED の色（次のスライドで置き換え）
- `data-stackchan-title`: 吹き出しの文字

**台本**
> スライドごとに、動きや表情を HTML の属性で指定できます。
> 発表者が手で設定をいじる必要はありません。

**注意（発表前に伝える）**
> 手動で操作している間は、スライドによる首の動きは行いません。
> 公開されている https のページからは、ws:// に接続できません。その場合は、ローカルに保存して開きます。（revealjs-bridge の README の手順）
> ただし、HUD（(C)）を使うデッキは、ローカル保存（file://）では HUD が動きません。PC の `serve.py` 経由（http://localhost）で開きます。

**[要確認]**: ブラウザ側の表示（吹き出しや LED）の実際の見え方は、このセッションでは確認していません。デモ前に実機で確かめてください。

## 7. 状態音（接続・ARM・モード変更）

**スライド**: タイミングと音の対応表（README の「状態音」の表）

**台本**
> QGC の状態が変わった瞬間に、1 回だけ音を鳴らします。
> 接続、切断、ARM、DISARM、モード変更です。
> 音を鳴らしている間は口だけを動かし、吹き出しと首は動きません。
> 音は今は仮のビープ音です。同じファイル名で差し替えられる作りになっています。
> 設定の「状態音」をビープにすると、どの状態でも同じ音になります。

## 8. 設定画面（機体の中で操作する）

**スライド**: 設定画面のスクリーンショット（右上をタップして開く）

**台本**
> 機体の右上隅をタップすると、設定画面が開きます。
> スライドモードと挨拶、MAVLink と状態音、音量と明るさ、Wi-Fi の候補を切り替えられます。

> Wi-Fi の SSID は機体では入力できません。候補からの選択のみです。

## 9. 位置と高度の方針

**スライド**: 指示書からの変更点（GPS を使わない → スマホの位置を Worker 経由で使う）

**台本**
> 当初の指示書では GPS を使わない想定でした。今は、スマホの最後の位置を Cloudflare Worker から取って、位置として送っています。
> 位置は、スマホが報告した最後の値です。古くなることがあります。
> 機体がスマホと一緒にいない場合は、この位置は機体の位置とは一致しません。
> 高度は、気圧センサーを付けたあとに、起動時を 0 とした相対高度で送る予定です。今は気圧センサーがないので、0 を送っています。
